# פרוטוקול שיגור — מסי

## הלוג היומי — `docs/ceo/messi/<YYYY-MM-DD>.md`

```
# מסי · <YYYY-MM-DD>

## תור
- [x] 1. <כותרת> · גו 10:20 · שוגר 10:22 · הושלם 10:41 · <לינק תוצר>
- [!] 2. <כותרת> · גו 10:45 · שוגר 10:46 · כשל 11:04 — <סיבה קצרה>; **עדיין פתוח**
- [~] 3. <כותרת> · גו 11:05 · שוגר 11:05 · רץ
- [ ] 4. <כותרת> · גו 11:06 · ממתין (אחד-אחד) — ⊥ באוויר, `תאריך התחלה` עוד ריק

## ספקים
### 1. <כותרת>
מטרה:        <משפט אחד — מה יהיה נכון אחרי>
ריפו/נתיבים: <מפורש; קריאה-בלבד ⇒ "אין כתיבה">
done-criterion: <מכני — פקודה/שאילתה + פלט צפוי. חובה לכל ספק כותב>
גבולות:      **⊥ merge · ⊥ deploy · ⊥ מיגרציית פרוד.** יורש את
             `.claude/skills/messi/SKILL.md` §גבולות במלואו — רשימת הנתיבים
             המותרים שם ממצה **וגם עליך**; נתיב ∉ הרשימה ⇒ ⊥ כתיב.
             <+ מה עוד ⊥ לגעת במשימה הזאת>
נושן:        <URL המשימה>

## אירועים
- CHECKPOINT 13:00 clean
- FAILURE 14:22 <ספק 2>: <סיבה, פלט גולמי מקוצר>
- GATE 17:10 נגררת: <שם> · חוסם <X>
```

שורות `GATE` נכתבות ע"י **שער הסגירה של day-close** — זו הכתיבה היחידה של הריטואלים
לקובץ הזה מלבד ניקוז ה-fallback. זה מה ש-day-open קורא למחרת ומציג כ"נגררות".

### דקדוק שורת `CHECKPOINT` — קנוני, מקור יחיד

```
CHECKPOINT <HH:MM> clean
CHECKPOINT <HH:MM> slipping <N>: <שם> (<מצב>) · <שם> (<מצב>)
CHECKPOINT <HH:MM> FAILURE <סיבה>
```

`<HH:MM>` = שעת IL. שלוש הצורות ⊥ מתחלפות: `clean` = רץ ונקי · `slipping` = רץ ומצא ·
`FAILURE` = **⊥ הצליח לבדוק**. שער ה-day-close מבדיל ביניהן; ⊥ לנסח וריאנט רביעי.

## חוקים
1. הספק נכתב **לפני** השיגור. סוכן הרקע מקבל את הספק בלבד — ⊥ את שיחת הצ'אט.
2. קריאה-בלבד ⇒ מותר בלי done-criterion ובלי גבולות; **כותב ⇒ שניהם חובה** —
   `done-criterion` מכני **וגם** `גבולות` מפורשים. חסר אחד מהם ⇒ ⊥ משוגר.
   **תוכן ה-`גבולות` ⊥ חופשי — שני חלקים, שניהם מילוליים בכל ספק כותב:**
   (א) **`⊥ merge · ⊥ deploy · ⊥ מיגרציית פרוד`** · (ב) הפניה מפורשת:
   *"יורש את `.claude/skills/messi/SKILL.md` §גבולות במלואו"*.
   הסיבה מכנית, ⊥ טקסית: לפי חוק 1 הספק הוא **כל הקונטקסט** של הסוכן. ספק שלא
   אומר את זה ⇒ הסוכן בוט ונופל ל-`CLAUDE.md` §Authorization, שמתיר merge של PR
   ו-deploy/מיגרציית-פרוד אוטונומיים. **חסר אחד משני החלקים = ספק פגום ⇒ ⊥ משוגר**,
   בדיוק כמו `done-criterion` חסר. השורה בתבנית למעלה היא הנוסח — להעתיק, ⊥ לנסח מחדש.
3. **יחס ל-`verification.md` §א':** אותם שדות, עם דלתא אחת מוצהרת —
   `פרויקט בנושן: <URL או "אין">` הוחלף ב-`נושן: <URL המשימה>` (מסי עובד ברמת
   **משימה**, ⊥ פרויקט). טבלת ה-✅/❌ של `done-criterion` — **זהה, ⊥ משוכפלת כאן**:
   הסטנדרט המכני נקרא משם.
4. `תאריך התחלה` נחתם כשהשורה הופכת ל-`[~]` — **שיגור בפועל, ⊥ רגע הגו**
   (בקר 2026-08-05). שורת `- [ ]` בתור = טרם באוויר.
5. אחד-אחד: משבצת `[~]` אחת לכל היותר. **הבא בתור משוגר רק אחרי שהשורה הנוכחית
   יצאה מ-`[~]`** — `[x]` בסיום, **`[!]`** בכשל. שתי שורות `[~]` בו-זמנית = באג
   (`[~]` ⟺ באוויר, חוק 4 — שתיים כאלה שוברות את הזהות).
6. סיום ⇒ סימון `[x]` + `תאריך השלמה` בנושן + ✓ בצ'אט. כשל/45 דק' ⇒ **`[!]`**
   (כשל, **עדיין פתוח**) + `FAILURE` באירועים + שורה רועשת בצ'אט.
   **`[!]` מפנה את המשבצת, ⊥ את הלולאה:** בנושן היא נשארת באוויר (`תאריך השלמה` ריק,
   `תאריך התחלה` חתום) ועולה בשער 17:00; בלוג היא כבר ⊥ `[~]`, ∴ הבא בתור יכול לצאת.
7. הלוג הוא האמת על **"אושר-ולא-רץ"** — הצ'קפוינט משווה תור מול נושן. ההגדרה המלאה
   נעולה ב-`SKILL.md` §mode=checkpoint 4; בקיצור: שורת `- [ ]` שקיבלה גו וטרם שוגרה,
   **כשאין `[~]` בלוג כלל** או **כש-`[~]` החוסם חצה 45 דק'**. ממתין מאחורי `[~]` חי
   ותקין = תור בריא, ⊥ מחליקה.
8. **הלוג נדחף לגיט בסוף כל ריצה** (`SKILL.md` §ביצוע 7), בנתיבים מפורשים.
   ⊥ `git add -A`. סשן שנגמר בלי push = לוג שלא היה.

## inbox-fallback — `docs/ceo/messi/inbox-fallback.md`
שורות `- [ ] <הזריקה המלאה> · נזרק <timestamp>`. ניקוז ⇒ סימון `- [x]` + שורת
הנושן שנוצרה. הקובץ ⊥ נמחק — היסטוריה זולה, אובדן יקר.
זה הבעלים של סמנטיקת הניקוז — הריטואלים והצ'קפוינט מצביעים לכאן, ⊥ מנסחים מחדש.

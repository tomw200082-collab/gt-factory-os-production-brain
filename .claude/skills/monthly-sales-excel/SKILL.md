# monthly-sales-excel — האקסל החודשי → דרופבוקס

שפת עבודה: **עברית**. המטרה: בכל 1 לחודש בבוקר, החודש שנסגר יושב מלא באקסל
בתיקייה של תום בדרופבוקס — בלי שאף אחד נגע בזה.

**חלוקת העבודה (תום, 2026-08-25):** האקסל **פעם בחודש** · הארטיפקט **פעם בשבוע**
(`weekly-sales-report`, רביעי 07:30). שתי ריצות נפרדות, אותו pipeline עובדות.

## עוגנים קבועים

- **יעד:** דרופבוקס `/Business/Sales` (team space, `root_namespace_id=13784336419`).
- **שם קובץ:** `מכירות MM.YY.xlsx` — MM/YY של **החודש שנסגר**. 1/9/2026 ⇒ `מכירות 08.26.xlsx`.
- **תוכן:** ינואר של אותה שנה → החודש שנסגר (YTD קלנדרי), שני גיליונות:
  `לקוחות <שנה>` ו-`לקוח × מוצר`. ב-1 בינואר החלון הוא ינואר–דצמבר של השנה שנסגרה.
- Scripts: `gt-factory-os/scripts/sales-report/` · השאילתה נעולה ב-`orders_bulk.graphql`.
- שיטה מלאה: `Sales-Machine/recipes/sales-report.md` (אותו בסיס עובדות, אותם 5 שערים).
- בסיס נעול: כל ₪ ללא מע״מ (המחיר השמור) · `discountedTotalSet` · חודש לפי שעון ישראל ·
  מבוטלות מוחרגות · עמודות המס/net של שופיפיי אסורות · `amountSpent` אסור.
- מייל: `tom@gteveryday.com` בלבד. אין שום פנייה ללקוח.

## הריצה חייבת לרוץ בלי MCP

הראוטין יורה **סשן חדש בלי connectors** — אין Shopify MCP, אין Gmail MCP, אין Dropbox MCP
(אומת בעת יצירת הראוטין, 2026-08-25). לכן כל שלב עובר ב-HTTP ישיר:

| צורך | בלי MCP |
|---|---|
| משיכת הזמנות | `curl` ל-`/admin/api/2025-07/graphql.json` עם `SHOPIFY_ADMIN_API_TOKEN` |
| עוגן ShopifyQL | `fetch_shopifyql.py` (Admin API; ראו המלכודות למטה) |
| העלאה לדרופבוקס | `upload_dropbox.py` (Dropbox API) |
| אימות ההעלאה | `upload_dropbox.py` קורא בחזרה `files/get_metadata` בעצמו |
| מייל | `curl` ל-webhook של Make → Gmail (ראו סעיף 9) |

יש MCP בסשן (ריצה ידנית) — מותר להשתמש בו, אבל **אסור לבנות עליו**; מה שנשען עליו
ייפול ב-1 לחודש בשקט.

## אישורי דרופבוקס (חובה — בלי זה אין העלאה)

`upload_dropbox.py` לוקח את הראשון שמוגדר:

| מסלול | משתני סביבה |
|---|---|
| A — Dropbox API (מועדף) | `DROPBOX_APP_KEY` + `DROPBOX_APP_SECRET` + `DROPBOX_REFRESH_TOKEN` |
| B — Make webhook | `GT_DROPBOX_WEBHOOK` (תרחיש Make שמחזיק את חיבור הדרופבוקס) |

אין אף אחד מהם ⇒ הסקריפט יוצא `2` ואומר בדיוק מה חסר. **לא ממציאים מסלול חלופי,
לא כותבים CSV במקום, לא שולחים את הקובץ ל"איפשהו אחר".** שולחים לתום מייל
״האקסל נבנה ואומת אבל לא הועלה — חסר אישור דרופבוקס״ + הקובץ בצ׳אט, וזהו.
ה-MCP של דרופבוקס **לא** יודע להעלות בינארי — `create_file` הוא טקסט בלבד.

## צעדים

1. **חלון:** `END` = החודש שנסגר (שעון ישראל). ב-1/9/2026 ⇒ `END=2026-08`.
2. **משיכה:** `bulkOperationRunQuery` עם `orders_bulk.graphql` כמות שהוא,
   `<START>` = (END − 24 חודשים) פחות יום. Poll עד `COMPLETED`, הורדת ה-JSONL אל
   `<workdir>/raw/orders.jsonl`. לרשום את `completedAt` בשעון ישראל — חותמת הטריות.
3. **עוגן בלתי-תלוי:** `python3 fetch_shopifyql.py <START> shopifyql_month.json`.
   הסקריפט עוטף שלוש מלכודות שנמדדו בשטח (2026-08-25) — ⊥ לכתוב את הקריאה ידנית:
   - ה-Admin API קורא לעמודה `returns`; ה-MCP קורא לאותם מספרים `sales_reversals`.
     בקשה ל-`sales_reversals` מול ה-Admin API חוזרת **HTTP 200** עם
     `Column Not Found` בתוך `parseErrors` ו-`tableData: null` — כשל שקט.
     אומת שווה-ערך: 2026-07 ‎−114,414.74 · 2026-08 ‎−448,004.12 בשתי הדרכים, 25/25 חודשים.
   - צורת `rows` השתנתה בין גרסאות API (מערכים ≤2026-01, אובייקטים ≥2026-07).
   - כל התאים חוזרים כ**מחרוזות**; בלי המרה `build_facts.py` נופל על `float - str`.
4. **בנייה:** להעתיק את הסקריפטים ל-workdir, ואז
   `GT_RANGE_END=<END> python3 build_facts.py`.
5. **שערי חובה** (מ-`out/gates.json` + `analyze_bridge.py`) — זהים לשבועי:
   - התאמת הזמנות מול ShopifyQL (כולל מבוטלות): **מדויק בכל החודשים המלאים**.
   - זהות חלון-מלא מול `total_sales`: **|Δ| ≤ 0.5%**.
   - **החודש שנסגר חייב להיות מלא** — הוא לא יופיע ב-`fact.partial`. אם כן ⇒ עצירה.
   - SKU חדשים שאינם במיפוי נופלים לדלי ההיסטורי הגלוי; מעל ₪20K בחודש האחרון —
     לציין במייל שנדרש עדכון מיפוי (לא חוסם).
6. **אקסל:** `GT_EXCEL_END=<END> GT_PULLED_AT=<ISO שעת המשיכה> python3 build_excel.py`
   → `מכירות MM.YY.xlsx`. הסקריפט מסרב לייצר קובץ ששמו חודש שאינו בטבלת העובדות.
7. **העלאה:** `python3 upload_dropbox.py "<הקובץ>"` (יעד ברירת מחדל `/Business/Sales`,
   `mode=overwrite` ⇒ ריצה חוזרת מחליפה, לא מכפילה).
8. **אימות אחרי הכתיבה — חובה:** `upload_dropbox.py` קורא את הקובץ בחזרה
   (`files/get_metadata`) ומשווה גודל ו-`content_hash`; פער ⇒ יציאה בשגיאה.
   מדווחים "הועלה" רק על `"verified": true` שחזר מהסקריפט.
9. **מייל לתום** — הערוץ המאומת של הגרדיאן, ⊥ Gmail MCP (אין בסשן):
   `curl -sS -X POST "https://hook.eu1.make.com/8yie1tl89bxsq8qqp6o47qydfr8cguji"
   -H "Content-Type: application/json" -d '{"subject":"...","html":"..."}'`
   → תרחיש Make `GT Guardian — Daily Email` (6439326) → tom@gteveryday.com. לוודא HTTP 200;
   לא-200 ⇒ לומר את זה מפורשות בסיכום הריצה. עברית, קצר:
   - נושא: `אקסל המכירות של <חודש עברי> בדרופבוקס`
   - גוף: (א) שם הקובץ + הנתיב. (ב) ״<חודש> נסגר על ₪X (±% מול <חודש קודם>, ±% YoY);
     סה״כ <שנה> עד כה ₪Y.״ (ג) שורת ״מה בולט״: הלקוח עם השינוי הגדול ביותר בחודש
     שנסגר (מספר אחד, לא רשימה). (ד) אם נפתח חריג מיפוי — שורה אחת עליו.

## כשל = אין העלאה

שער נופל ⇒ **לא מעלים קובץ**. מייל קצר: ״האקסל של <חודש> לא הועלה — <הסטייה
במספרים>. הקובץ הקודם בדרופבוקס נשאר כמו שהוא.״ כלל הברזל של תום: עדיף פחות —
אסור לשקר. קובץ שגוי בתיקייה של תום גרוע מתיקייה בלי קובץ.

## P-1 · מעגל פקודת הייצור — recipe→execution→QC (DIRECTION_AGREED 2026-07-21)

**הבעיה (טום):** אין בדיקת איכות שוטפת ("לא תקין"); פער מתכונים↔ביצוע (F-1); צריכת חומרים נגזרת ולא מאושרת.

**מצב היום (verified):** דיווח ייצור = Backflush — דניס מדווח תפוקה בלבד; המערכת גוזרת צריכה מה-BOM (פיצוץ דו-ראשי PACK+BASE) ופוסטת `PRODUCTION_OUTPUT`+`PRODUCTION_CONSUMPTION`. סטיות (שפיכה/החלפה/חוסר) לא נתפסות — מתגלות רק בספירות, בלי סיבה. הסקיל `production-order` (gt-factory-os) קיים: דף A4 מודפס פר מוצר מה-BOM החי + תוכנית, tick-box לשורה, קריאה-בלבד, לא כותב כלום.

**העיצוב המוסכם-בכיוון (טום הציע; קלוד עידן):** פקודת ייצור כדף חי במערכת, שלושה שלבים:

- **שלב א — פקודה (לפני):** נוצרת מהתוכנית המקובעת פר יום/אצווה; פורמט מתכון; כמויות סקיילד לאצווה; סדר לפי המחסן. אישור דניס בפתיחה = שער זמינות חומרים ("הכל זמין, מתחיל") — תופס חוסר לפני הבישול.
- **שלב ב — צ'ק-ליסט ביצוע (תוך כדי):** ✓ פר שורה (חומר/אריזה/תווית/פקק). **קריטי: ברירת-מחדל-מאושרת, עריכה רק בחריגה** — ✓ = "כמו שכתוב"; סטייה פותחת כמות + קוד סיבה (נשפך/חסר/הוחלף/אחר). ⊥ הקלדת כמויות מלאה (מלכודת ידועה — קורס בצוות קטן). הצריכה שנפסטת = השורות המאושרות. הערת רצפה: דניס שוקל תוך-כדי-בישול (לא kitting מראש) — הצ'ק-ליסט חי בעמדת השקילה/בישול, מובייל.
- **שלב ג — סגירה (אחרי):** תפוקה בפועל (+שבר/פסולים כפחת); **QC חובה: Brix + pH עם טווח תקין פר מתכון** — חריגה חוסמת סגירה או דורשת אישור טום (בקרה, לא יומן); קוד אצווה אוטומטי (תאריך+פריט) על התפוקה; הכמות הסגורה = הקליטה של מקסים (תפר s1 מקבל רישום מערכתי חינם).

**תוספות (קלוד):** (1) דוח פערים אוטומטי פר אצווה — תוכנן↔בפועל; מזין את עבודת המתכונים של אלכס (OD-9) ומדייק COGS; (2) קודי סיבה = רשימה סגורה 4-5; (3) קוד אצווה על תפוקה בלבד.
**⊥ v1:** מעקב אצוות חו"ג נכנס / FEFO / תוקפים / משקלים משולבים (נעול מחוץ ל-v1 ב-CLAUDE.md). גנאלוגיה מלאה = עתיד.
**ארכיטקטורה:** טופס→אירוע→ledger כרגיל (form_type חדש); הפיצוץ הדו-ראשי הקיים = מקור הצ'ק-ליסט במקום חישוב שקט; הסקיל `production-order` נשאר מנוע ההדפסה מאותם נתונים.
**Routing כשיאושר:** backend-db lane (schema+handlers) + portal lane (הדף) + UX handoff; RUNTIME_READY gate.

## P-5 · סקילים אחרי יציבות — תאום דיגיטלי פר תפקיד, נמדד ב-drift (DIRECTION_AGREED 2026-07-22)

**ההחלטה (טום 2026-07-22):** לא בונים סקילים-עוזרים לפני שהתפעול מדויק. קודם מריצים את הארגון החדש ידנית; הסקילים נבנים אחר כך, תהליך-אחר-תהליך, ככל שכל אחד מוכיח יציבות.

**למה קודם תפעול (הנמקה):**
1. אוטומציה של תהליך שעוד זז = לקבע את הכאוס. `org_map` = מודל/השערה עד שפוגש מציאות; סקיל על מודל לא-מאומת יורש את טעויותיו ומריץ אותן מהר יותר.
2. שכבה ידנית (כרטיס תפקיד, כלל ברזל) זולה לשינוי; סקיל יקר לשינוי + הצוות כבר בנה עליו הרגלים. תנודות נספגות בשכבה הזולה לפני קיבוע ביקרה. = "פשוט לפני מורכב בלתי-הפיך" (CLAUDE.md tiebreaker).
3. אין דרך לדעת שהתפעול מדויק בלי להריצו — צריך את החיכוך האמיתי.

**ניואנס (⊥ להגזים לכיוון השני):** להבחין בין "סקיל = תאום/עוזר" (מריץ במקום אדם — **מחכה**) לבין "המערכת שקולטת את העבודה" (מעגל פקודת הייצור P-1, שערי QC — **המכשיר-מדידה של התפעול**, מבשיל במקביל כי בלעדיו התפעול עיוור).

**המנגנון — יציבות מזכה סקיל:** תהליך "מזדכה" בתאום כשרץ נקי — אחראי יציב, כללי ברזל לא נשברים, תפר לא מפיל באטונים. **אותו drift check + מבחן Done (SPEC §V/§C) אומרים אילו תהליכים כשירים.** הסקיל = פרס על יציבות, פר-תהליך, ⊥ big-bang.

**הארכיטקטורה (לכשיגיע הזמן):**
- **תאום דיגיטלי פר תפקיד, נגזר מ-`org_map`** (אחריות + כללי ברזל + תפרים + ספי ₪). משנים מפה → סקיל מתעדכן; מוסיפים עובד → תאום חינם. אפס דריפט (מקור אחד). = "חוזה ההפעלה החי" רץ בפועל.
- **דימר אחד, 3 עוצמות** — פותר גם יומיום וגם חירום במנגנון אחד: 🟢 עוזר (עובד נוכח, קופיילוט שאוכף כללי ברזל) · 🟡 מחליף (עובד חסר, מוביל לא-מומחה צעד-צעד — **יותר** ריסון) · 🔴 טייס אוטומטי (אין אף אחד, קלוד מריץ חלקי-מערכת בגבולות ההרשאה).
- **שכבת תפרים (באטון):** סקילים מוסרים זה לזה ב-8 התפרים (דניס-סגירה פולט כמויות → מקסים-קליטה מקבל). תפר = אירוע מערכת, לא תקווה.
- **מצב אימון:** הסקיל מלמד אדם שני את התפקיד בזמן שהמומחה עדיין כאן → הורג SPOF בשגרה (קריטי לדניס). גם = מדריך אונבורדינג לגיוסים.
- **קונסולת חירום לטום ("מי חסר היום"):** קלט = מי נעדר; פלט = המסלול הקריטי שלו מ-`org_map`, מה חייב-היום מול מה-שיחכה, הרצת חלקי-מערכת, וסימון מה דורש גוף אנושי.
- **כרטיס תפקיד (נייר לקיר, T10) + סקיל (נייד) = אותו מקור** (`org_map` entry).

**רצף:** עיצוב (הפרזנטציה) → הפעלה ידנית (כרטיסים + כללי ברזל + תדריך + תפרים) → מדידה (מפה + drift; P-1 מבשיל כמכשיר) → תאומים פר-תהליך ככל שכל אחד מזדכה.

**⊥ / הכנות:** 🟡/🔴 = יותר שמירות לא פחות (לא-מומחה = סיכון גבוה); אמת מלאי קדושה; frozen flags נשארים קפואים; ⊥ מעקף לחוק הבעלים-האחד (הסקיל מנתב לאחראי, לא עוקף); External-action authorization boundaries חלים.

## P-1 · מעגל פקודת הייצור — recipe→execution→QC (DIRECTION_AGREED 2026-07-21)

**הבעיה (טום):** אין בדיקת איכות שוטפת ("לא תקין"); פער מתכונים↔ביצוע (F-1); צריכת חומרים נגזרת ולא מאושרת.

**מצב היום (verified):** דיווח ייצור = Backflush — דניס מדווח תפוקה בלבד; המערכת גוזרת צריכה מה-BOM (פיצוץ דו-ראשי PACK+BASE) ופוסטת `PRODUCTION_OUTPUT`+`PRODUCTION_CONSUMPTION`. סטיות (שפיכה/החלפה/חוסר) לא נתפסות — מתגלות רק בספירות, בלי סיבה. הסקיל `production-order` (gt-factory-os) קיים: דף A4 מודפס פר מוצר מה-BOM החי + תוכנית, tick-box לשורה, קריאה-בלבד, לא כותב כלום.

**העיצוב המוסכם-בכיוון (טום הציע; קלוד עידן):** פקודת ייצור כדף חי במערכת, שלושה שלבים:

- **שלב א — פקודה (לפני):** נוצרת מהתוכנית המקובעת פר יום/אצווה; פורמט מתכון; כמויות סקיילד לאצווה; סדר לפי המחסן. אישור דניס בפתיחה = שער זמינות חומרים ("הכל זמין, מתחיל") — תופס חוסר לפני הבישול.
- **שלב ב — צ'ק-ליסט ביצוע (תוך כדי):** ✓ פר שורה (חומר/אריזה/תווית/פקק). **קריטי: ברירת-מחדל-מאושרת, עריכה רק בחריגה** — ✓ = "כמו שכתוב"; סטייה פותחת כמות + קוד סיבה (נשפך/חסר/הוחלף/אחר). ⊥ הקלדת כמויות מלאה (מלכודת ידועה — קורס בצוות קטן). הצריכה שנפסטת = השורות המאושרות. הערת רצפה: דניס שוקל תוך-כדי-בישול (לא kitting מראש) — הצ'ק-ליסט חי בעמדת השקילה/בישול, מובייל.
- **שלב ג — סגירה (אחרי):** תפוקה בפועל (+שבר/פסולים כפחת); **QC חובה: Brix + pH עם טווח תקין פר מתכון** — חריגה חוסמת סגירה או דורשת אישור טום (בקרה, לא יומן); קוד אצווה אוטומטי (תאריך+פריט) על התפוקה; הכמות הסגורה = הקליטה של מקסים (תפר s1 מקבל רישום מערכתי חינם).

**תוספות (קלוד):** (1) דוח פערים אוטומטי פר אצווה — תוכנן↔בפועל; מזין את עבודת המתכונים של אלכס (OD-9) ומדייק COGS; (2) קודי סיבה = רשימה סגורה 4-5; (3) קוד אצווה על תפוקה בלבד.
**⊥ v1:** מעקב אצוות חו"ג נכנס / FEFO / תוקפים / משקלים משולבים (נעול מחוץ ל-v1 ב-CLAUDE.md). גנאלוגיה מלאה = עתיד.
**ארכיטקטורה:** טופס→אירוע→ledger כרגיל (form_type חדש); הפיצוץ הדו-ראשי הקיים = מקור הצ'ק-ליסט במקום חישוב שקט; הסקיל `production-order` נשאר מנוע ההדפסה מאותם נתונים.
**Routing כשיאושר:** backend-db lane (schema+handlers) + portal lane (הדף) + UX handoff; RUNTIME_READY gate.

## P-2 · ריבוע קליטה בדלת הספקים (PROPOSED)

**ההקשר (טום, Q2/Q5):** אין תפקיד קבלה מוגדר; שאיפה — דניס פותח; מסלול הקבלה חוצה את כל המבנה ולעיתים מפריע; מקובל כי חו"ג חייב להיות קרוב לבישול.
**ההצעה:** משטח ספק נעצר ב**ריבוע קליטה מסומן ליד כניסת הספקים** — הספק לא נכנס פנימה (היגיינה + אבטחה + אין צורך בליווי). בדיקה מול תעודת משלוח = שם, בדלת. העברה לעורף = דניס, ברגע נוח שלו (two-stage receiving). + כלל קדימות אחד במעבר: **עגלת תוצרת בדרך החוצה עוצרת הכל** (היא הכסף). שילוט בהתאם.

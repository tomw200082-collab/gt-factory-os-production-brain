**העמודות:**

| עמודה | סוג | הערה |
|---|---|---|
| `שם` | title | |
| `תאריך יעד` | date | |
| `תאריך השלמה` | date | **ככה מסמנים שבוצע.** `בוצע` הוא כפתור ולא ניתן לכתיבה |
| `בעל תפקיד` | multi-select | תום · אלכס · דורין · מקסים · דניס · עדי · אדי · אמיר. ⚠ **מיידן לא קיים כערך** |
| `גל` | select | גל 0–4 · שלב ב · שוטף · מנהלה |
| `מסלול` | select | שטח · מעבדה · ציר-אלכס · מנהלה |
| `פרויקטים` | relation | |
| `אחראי` | person | ⚠ **לא מקור אמת** — מוגבל למשתמשי Notion בלבד. הבעלות האמיתית ב־`בעל תפקיד` |

**שאילתה:** SQL מעל ה־collection URL. דוגמה — משימות פתוחות ליום מסוים:

```sql
SELECT "שם", "date:תאריך יעד:start" AS due, "בעל תפקיד" AS who, "גל" AS wave, url
FROM "collection://c6604298-2afb-8258-8026-87e9538244c3"
WHERE date("date:תאריך יעד:start") = date('YYYY-MM-DD')
  AND "date:תאריך השלמה:start" IS NULL
ORDER BY "גל"
```

## 4 · כללי הברזל של ניהול המשימות

1. **תאריך ושם־יום חייבים להסכים.** היה סחף שיטתי של יום אחד — לבדוק לפני שכותבים.
2. **אין תאריך יעד בשישי או בשבת.**
3. **לכל משימה בעל תפקיד.** גם אם תום אחראי על המון.
4. **משימה נסגרת, לא הרגל.** לא ״תמיד לרשום X״ אלא ״להטמיע את X ולוודא 5 ימים רצופים״.
5. **שורה אחת לכל תוצר.** לא לאגד שלושה תוצרים במשימה אחת.
6. **סימון ״בוצע״ = כתיבת `תאריך השלמה`.** עדכון של הרבה שורות בבת אחת הוא שינוי גורף וגלוי —
   לשאול את תום לפני.

## 5 · איך בונים לוז

1. **שולפים מ־Notion** את המשימות הפתוחות לאותו תאריך.
2. **קוראים את היומן** לאותו יום — האירועים הקיימים הם עוגנים, לא מזיזים אותם.
3. **מתאימים לאילוצי האנשים** מסעיף 1. האילוץ קובע את הסדר, לא ההיגיון.
4. **כותבים תיאור אמיתי בכל אירוע** — מה חדש אצל האדם הזה, מה כלל הברזל שהכי סביר שיישבר.
   המטרה: שתום לא יצטרך לפתוח מסמך אחר לפני כל שיחה.
5. **אזור זמן `Asia/Jerusalem`.** תמיד.
6. **משאירים חלון תגובה** ביום שמשיקים בו משהו. יום ראשון של תהליך חדש מייצר שאלות, ואם אין
   חלון — התשובה תהיה ״אחר כך״, וזה מה שהורג תהליך חדש.

- **קרטון הרכב = מיידן.** הרכב לא חוזר למפעל כל יום.

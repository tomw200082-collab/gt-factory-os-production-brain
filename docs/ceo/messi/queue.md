# תור העבודה של מסי

> הערוץ **היחיד** שדרכו סשן אחר מוסר עבודה למסי שתרוץ מהצד.
> נצרך ע"י `.claude/skills/messi/SKILL.md` §mode=worker (טריגר `messi-worker`).
> הקובץ ⊥ נמחק ו⊥ נגזם — שורות סגורות נשארות. היסטוריה זולה, אובדן יקר.

## איך מוסרים משימה

1. **append שורה** בפורמט למטה תחת §תור.
2. **commit + push** — `git add docs/ceo/messi/queue.md`. **מה שלא נדחף ⊥ קיים לוורקר**:
   הטריגר פותח סשן טרי שמושך את הריפו מאפס.
3. אופציונלי — לאיסוף מיידי במקום להמתין לריצה הבאה: להריץ את הטריגר `messi-worker`
   ידנית (Routines → Run now, או `fire_trigger`).

## פורמט השורה

```
- [ ] <משימה, שורה אחת> · מקור <מי/מה> · נזרק <YYYY-MM-DDTHH:MM+03:00> · done: <קריטריון מכני> · ריפו: <נתיב | "קריאה בלבד">
```

| שדה | חובה | מה נכנס |
|---|---|---|
| המשימה | תמיד | משפט אחד. מה יהיה **נכון** אחרי, ⊥ איך לעשות |
| `מקור` | תמיד | מי מסר — סשן, ריטואל, טום. לביקורת |
| `נזרק` | תמיד | חותמת זמן IL |
| `done:` | תמיד | **מכני** — פקודה/שאילתה + פלט צפוי. "שיהיה תקין" ⊥ קריטריון |
| `ריפו:` | למשימה כותבת | נתיבים מפורשים. קריאה-בלבד ⇒ `"קריאה בלבד"` |

`done:` רך או `ריפו:` חסר במשימה כותבת ⇒ הוורקר **⊥ משגר** — הוא מסב את השורה
למשימה בנושן לטום. זה מכוון: ספק בלי קריטריון מכני ⊥ ניתן לאימות
(`reference/dispatch.md` חוק 2).

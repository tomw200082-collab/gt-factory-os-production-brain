## 3. עקרונות עיצוב מחייבים (מהמחקר; מקור בסוגריים)

1. **קונטקסט = המשאב היקר.** כל ריטואל בסשן טרי; נתונים נשלפים בסקריפטים/שאילתות מוכנות, ⊥ קריאה גולמית חוזרת של נושן/DB. (Claude Code Best Practices)
2. **Progressive disclosure:** SKILL.md רזה (<500 שורות) + `reference/` שנטען לפי צורך + `scripts/` לפעולות שבירות. (Agent Skills docs)
3. **דרגות חופש:** קריאות/כתיבות נושן ו-DB = סקריפטים/מתכונים מדויקים (low freedom); תעדוף, רטרו וגריל = הנחיות שיקול-דעת (high freedom). (Agent Skills docs)
4. **לכל משימת-לילה קריטריון ״גמור״ מכני** — טסט, שאילתה, דיף צפוי. ⊥ ״לשפר את X״. (Best Practices)
5. **Explore→Plan→Execute מופרדים:** סגירת יום מייצרת ספק כתוב; הביצוע רץ בקונטקסט נקי מהספק. (Best Practices)
6. **צ׳קליסט + ולידציה חוסמת:** day-close לא מסתיים עד שהלו״ז עובר ולידציה — לכל אבן יש בלוק, אין overbooking, יש בלוק עומק אחד מאוחד. (Skills docs + Drucker)
7. **Workflows פשוטים > agent חופשי;** רק ביצוע הלילה אג׳נטי, וגם הוא בשערים. (Building Effective Agents)
8. **שערי אדם בנקודות הכרעה:** אישור תור לילה ב-17:00, שער merge בבוקר, halt על עמימות (`assumption_failure` — כבר תרבות הבית). (Building Effective Agents)
9. **Subagents לניקיון קונטקסט:** מוצ״ש עושה fan-out לתת-סוכנים (נושן / מפעל / יומן / מכירות) שמחזירים תקצירים; הסשן הראשי רק מסנתז ונועל. (Best Practices)
10. **אימות בקונטקסט טרי:** תוצרי הלילה נבדקים בבוקר ע״י subagent שלא ראה את ההנמקה — VERIFIED / NEEDS-REVIEW עם דיפים. (Best Practices)
11. **GTD:** כל פרויקט פעיל בלי next-action מוגדר = ״תקוע״ ומסומן במוצ״ש; משימה אמיתית = פעולה + אחראי + תאריך. (Allen)
12. **אבנים לפני חצץ:** 3 האבנים נקבעות ונכנסות ללו״ז לפני שהשבוע מתמלא; day-open פותח באבן של היום לפני כל דחוף. (Covey)
13. **מיקוד אחד:** day-open מציג עדיפות אחת ראשית; רטרו הערב כולל שאלת ״מה מפסיקים לעשות?״ קבועה. (Drucker)
14. **Waiting-on רץ:** כל האצלה = תאריך checkback; פריטים מזדקנים צפים אוטומטית — לבני אדם ולקלוד באותה מידה. (Drucker/Allen + HBR)
15. **תשומת הלב של טום = כמו חלון קונטקסט:** מסך ראשון מציג Level 1 בלבד (3 אבנים, בלוקים, 3 חריגים); הפירוט בהמשך/בדרילדאון. (סינתזה)

### 4.2 `weekly-opening` v2 (שדרוג הקיים)
- Stage 1 הופך ל-fan-out subagents: נושן (גאנט מלא: עיכובים, תקועים, waiting-on, עומס פר-אדם) · מפעל (מ-sunday-prep) · מכירות ₪ · יומן · PRs. כל אחד מחזיר תקציר.
- רטרו-קודם-נעילה (evaluator): ציון אבני שבוע שעבר לפני קביעת חדשות; החטאה חוזרת ⇒ הצעת שינוי בסקיל עצמו.
- ההצעה ל-3 אבנים נגזרת מ: פרויקטים אסטרטגיים בנושן (עדיפות+עיכוב) > משימות מזדקנות > הזדמנויות.
- נעילת אבנים ⇒ גם בלוקים ביומן הייעודי לשבוע (G5) + הקצאת משימות-קלוד לשבוע (G3).
- כתיבה חזרה: נושן (החלטות→משימות) · כרטיס שבוע · מראה registry · דשבורד · מייל.

### 4.3 `chief-of-staff-daily` (חדש) — שני מצבים
**day-open 07:30 (א׳–ה׳):**
1. רוכב על ריצת הגרדיאן של 06:30 (קורא את תוצריה — ⊥ מריץ SQL מחדש).
2. אימות תוצרי הלילה (subagent טרי): VERIFIED → מסומן בוצע בנושן + לינק; NEEDS-REVIEW → פריט ראשון במייל.
3. מרכיב את היום: אבן-היום · הבלוקים מהיומן · 3 חריגים מקס · waiting-on שהבשיל היום.
4. פלט: מייל קצר (Level 1 בלבד) + push + רענון דשבורד.

**day-close 17:00 (א׳–ה׳):**
1. רטרו היום: planned vs actual (יומן + נושן + דיווחי טום בצ׳אט), שאלת ״מה מפסיקים?״.
2. Sweep: משימות שהבשילו, תקיעות חדשות, checkbacks למחר.
3. בניית לו״ז מחר לפי `luz_rules.md` + ולידציה חוסמת (עיקרון 6).
4. הצעת תור-לילה לקלוד (עם ספקים לפי `verification.md`).
5. **שער טום:** הודעה אחת עם הלו״ז + התור → אישור בהקשה → כתיבת הבלוקים ליומן + חימוש ריצת הלילה + עדכוני נושן.

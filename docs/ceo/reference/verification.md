# ספק משימת-לילה + אימות בוקר

> שני חצאים של אותו חוזה: **ה-17:00 כותב ספק שאפשר לאמת מכנית. ה-07:30 מאמת אותו בקונטקסט שלא ראה את ההנמקה.**
> ⊥ ״לשפר את X״. משימה בלי קריטריון-גמור מכני ⊥ נכנסת לתור. זה החוק היחיד שמונע ״הרצתי משהו בלילה, נראה בסדר״.

## חלק א׳ — ספק משימת-לילה (נכתב ב-day-close)

כל פריט בתור נכתב **בפורמט הזה בדיוק**, בכרטיס השבוע תחת `## תור לילה <YYYY-MM-DD>`:

```
### N. <כותרת קצרה>
מטרה:        <משפט אחד — מה יהיה נכון אחרי, ⊥ מה לעשות>
ריפו/נתיבים: <רשימה מפורשת. ⊥ "הקוד הרלוונטי">
done-criterion: <בדיקה מכנית — פקודה + פלט צפוי>
גבולות:      <מה ⊥ לגעת בו>
פרויקט בנושן: <URL או "אין">
```

### `done-criterion` — מה נחשב מכני

| ✅ מכני | ❌ ⊥ מכני |
|---|---|
| `cd api && npm test` → `N/N pass`, ⊥ ירידה מהבסיס | ״הטסטים עוברים״ |
| `npm run typecheck` → 0 שגיאות | ״הקוד נקי״ |
| `git diff --stat` נוגע **רק** בנתיבים שברשימה | ״שינוי ממוקד״ |
| שאילתה מחזירה `0 rows` / ערך מדויק | ״הנתונים תקינים״ |
| הקובץ `X` קיים ומכיל סעיף `Y` | ״כתבתי מסמך״ |
| `rebuild_verifier() = 0` | ״לא שברתי מלאי״ |

**⊥ ניתן לנסח קריטריון מכני ⇒ המשימה ⊥ למנוע הלילה.** היא הופכת לבלוק עומק בלו״ז של טום. זו התשובה הנכונה, ⊥ כישלון.

## חלק ב׳ — מנוע הלילה

- נורה **רק** אחרי אישור טום ב-day-close. אין אישור ⇒ אין `run_once` ⇒ אין ריצה. ⊥ רוטינה קבועה.
- **משימה = סשן/סאב-אייג׳נט טרי, מהספק בלבד.** ⊥ מעבירים לתוכו את שיחת ה-17:00 — הספק הוא כל הקונטקסט. זה מה שמאפשר לאימות הבוקר להיות עצמאי.
- **תוצרים מותרים:** ענף + PR **טיוטה** · מסמך ב-`docs/**` · עדכון נושן (לפי `notion_contract.md`).
- **⊥ מותר:** merge · deploy · מיגרציית פרוד · מיילים/הודעות החוצה · כתיבה למערכות חיצוניות (Shopify/LionWheel/Green Invoice) · דגלים קפואים · `stock_ledger` / projections. **שער הבוקר הוא האישור** (G6).
- **כישלון = רועש.** נכתב ל-`docs/ceo/night/<YYYY-MM-DD>.md` (מה רץ · מה עבר · מה נפל · הפלט הגולמי) ומדווח ראשון ב-day-open. ⊥ להיעלם בשקט — זה V9 של הגרדיאן, אותו כלל.
- **לוג הלילה נדחף לגיט בסוף ריצת הלילה — חובה, ⊥ רשות.** `run_once` הוא סשן טרי שמת בסופו, ואימות הבוקר הוא סשן טרי **אחר**: לוג שלא נדחף פשוט ⊥ קיים ב-07:30, ו-day-open ידווח ״לא רץ תור אתמול״ בשקר — בדיוק הכשל שהוא אמור לתפוס. נתיב מפורש, **⊥ `git add -A`**:
  ```bash
  git add docs/ceo/night/<YYYY-MM-DD>.md
  git commit -m "log(night): <תאריך> — <N> משימות · <M> נפלו" && git push origin HEAD
  ```
  ענף = זה שהסשן עליו. **ענף/PR-הטיוטה של המשימה עצמה נדחפים בנפרד** — ⊥ מעורבבים בקומיט הלוג, כדי שהמאמת יראה דיף נקי מול הספק.
- משימה שנתקעת >45 דק׳ ⇒ נעצרת, נרשמת `TIMEOUT`, התור ממשיך לבאה.

## חלק ג׳ — אימות בוקר (day-open שלב 2)

מריצים בקונטקסט **טרי**. המאמת מקבל **רק**: הספק + הדיף בפועל. **⊥ מקבל** את נימוקי הלילה, ⊥ את מה שהסוכן טען שעשה.

לכל פריט, פסק דין אחד:

| פסק | תנאי | פעולה |
|---|---|---|
| **VERIFIED** | `done-criterion` רץ בפועל ועבר ∧ הדיף ⊆ הנתיבים המוצהרים | סמן בוצע בנושן + לינק לתוצר |
| **NEEDS-REVIEW** | הקריטריון נפל · הדיף חורג · התוצר ⊥ קיים · טענה בלי הרצה | **פריט ראשון במייל הבוקר**, עם הדיף |
| **BLOCKED** | ⊥ התחיל (תלות/הרשאה/timeout) | חוזר לתור עם הסיבה |

**⊥ VERIFIED על סמך דיווח עצמי.** ״הטסטים עברו״ מהסוכן ⊥ עדות — המאמת מריץ בעצמו. סוכן שטוען הצלחה וה-done-criterion נופל ⇒ NEEDS-REVIEW **ועוד שורה** בלוג הלילה: `SELF_REPORT_MISMATCH`. תבנית חוזרת = באג בספק, ⊥ בסוכן.

**⊥ merge אוטומטי, לעולם.** גם VERIFIED. הטיוטה ממתינה לטום.
